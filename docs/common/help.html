KOTLIN PROGRAMMING EXERCISES / 共通資料・授業サポート

困ったとき

コードが赤くなった、アプリが動かない、原因が分からない。
エラーに向き合い、自分で解決するための調べ方をまとめています。

  1. 1. エラーが起きたときの調べ方
  2. 2. 共通資料を活用する
  3. 3. どうしても解決しないときは（完成プロジェクトの確認）

1. エラーが起きたときの調べ方

プログラミングでエラーが出るのは自然なことです。エラーメッセージには「どのファイルの何行目で、何が問題か」が書かれています。焦らずに上から順に確認しましょう。

  1. 各単元の「困ったとき」表を確認する
    教科書の末尾にある「困ったとき」には、その単元でよくある間違いと確認場所がまとまっています。
  2. 最初の赤い行を見る
    エラーが何行も出ているときは、一番上の「最初の赤い行」を直します。最初の1つを直すと、あとのエラーがまとめて消えることがよくあります。
  3. 直前のSTEPと見比べる
    手順を1つ飛ばしていないか、大文字・小文字やスペル（綴り）が教科書と違っていないかを確認します。
  4. 先生に質問するときは
    「STEP番号・編集したファイル・最初の赤い行・実行した操作」を伝えると、原因が早く分かります。

2. 共通資料を活用する

状況に応じて、次の共通資料を参考にしてください。

困っていること参考にする共通資料
授業前の準備や教材の配置を確認したい共通資料：授業を始めるまでの準備 を確認します。
Android Studioのバージョンが違う共通資料：ちがうAndroid Studioのバージョンで進めるとき を確認します。
提出課題の作り方や提出方法を知りたい共通資料：提出課題とAPKの作り方 を確認します。

3. どうしても解決しないときは（完成プロジェクトの確認）

どうしても自分のコードの間違いが見つからないときや、プログラム本来の動きを確認したいときは、先生が作った完成プロジェクト（見本）を開いて自分のコードと見比べることができます。

完成プロジェクトは「答え合わせ用」です

完成プロジェクトからコードをそのままコピーしたり、完成プロジェクトを改造して提出しても、自分の課題の提出にはなりません。見本で違いを確認したら、必ず自分で作ったプロジェクトに戻り、自分の手で修正してください。

見本の開き方

  1. 書類（Documents）にある教材のフォルダ（kotlin-student-materials-日付）を開きます。
  2. その中にある samples フォルダから、該当する単元のフォルダ（例：K01HelloKotlin、A02CalcGame など）を確認します。
  3. IntelliJ IDEA または Android Studio の Open で該当フォルダを選んで開きます。
  4. 見本で正しいコードや動作を確認したら見本を閉じ、自分のプロジェクト（Documents/Kotlin/単元名）を開き直して作業を続けます。

取り違えに注意

見本と自分のアプリは同じプロジェクト名です。ウィンドウ上部に表示される保存先パスを確認し、見本のほうを編集してしまわないよう注意しましょう。
