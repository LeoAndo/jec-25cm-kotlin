提出課題と
APKの作り方

この授業の提出課題の説明です。自分で作ったAndroidアプリを1つ選び、アレンジを加えて、APKというファイルにして提出します。

1. 提出課題

この資料を使うのは、後半のAndroidの単元が終わってからです。前半のIntelliJ IDEAの単元だけが済んだ時点では、まだ進められません。提出する時期は、先生の案内に従ってください。

提出するもの

APKファイルを1つ。提出先は、先生が案内する場所です。

すること内容
選ぶ後半のAndroidの単元で自分が作ったプロジェクトから、好きなものを1つ選びます。
アレンジする選んだ1つに、自分なりの変更を加えます。文字の色を変えるだけでも構いません。
APKにするアレンジしたプロジェクトから、APKを作ります。アプリを1つのファイルにまとめたものです。
提出するできたAPKを、先生が案内する提出先に出します。

進め方

2. 1つ選ぶ→3. コピーを取る→4. アレンジする→5. APKを作る→6. 名前を変える→7. 提出する

番号は、下の見出しの番号と同じです。選ぶアプリは1つなので、2から7までを上から順に1回ずつ行えば終わります。

完成プロジェクト（見本）をそのまま出しても、提出にはなりません

教材のフォルダの samples に入っている完成プロジェクトは、先生が作った見本です。提出するのは、自分で作ったプロジェクトにアレンジを加えたものです。見本をそのままAPKにして出しても、提出として数えません。

2. アプリを1つ選ぶ

Finderで 書類 → Kotlin を開きます。この授業で自分が作ったプロジェクトのフォルダが並んでいます。この中から1つ選びます。

この教材には、A01HelloAndroid・A02CalcGame・A03GithubSearch・A04FunnyCamera の教科書が入っています。この4つのうち、自分で作って完成させたアプリが候補です。提出時期までに自分で作ったアプリから選びます。

選べるのは、後半のAndroidの単元で、Android Studio で作ったプロジェクトです。どの単元のものでも構いません。気に入っているもの、もっと変えてみたいものを選んでください。

前半の K01HelloKotlin は選べません

前半の単元で IntelliJ IDEA を使って作った K01HelloKotlin は、結果を文字で出すコンソールのプログラムです。スマートフォンにインストールするアプリではないので、APKを作る仕組みがありません。提出課題の対象は、Android Studio で作ったプロジェクトだけです。

samples フォルダの中のものは、選べません

教材のフォルダの samples に入っているのは、先生が作った完成プロジェクト（見本）です。選ぶのは、書類 → Kotlin のすぐ下にある、自分で作ったプロジェクトです。

最後まで作れていない単元も、教科書を見ながら完成させれば選べます。選べるものが1つもないときは、先生に相談してください。

3. アレンジの前に、コピーを取っておく

アレンジを始めると、どこを変えたか分からなくなったり、アプリが動かなくなったりすることがあります。そうなっても元に戻せるように、先にプロジェクトをまるごとコピーしておきます。

ここでは、選んだプロジェクトの名前を A01HelloAndroid として説明します。自分が選んだプロジェクトの名前に読み替えてください。

  1. Android Studioで、そのプロジェクトのウィンドウを閉じます。
  2. Finderで 書類 → Kotlin を開きます。
  3. アレンジするプロジェクトのフォルダ（A01HelloAndroid）を右クリックします。
  4. 出てきたメニューから 複製 を選びます。

成功の目印

同じ場所に A01HelloAndroidのコピー というフォルダができている。

コピーのほうは、開かずにそのまま置いておきます。アレンジするのは、元の名前のほう（A01HelloAndroid）です。

コピーに時間がかかることがあります

Androidのプロジェクトには、ビルドのときに作られたファイルが入っています。そのぶんフォルダが大きいので、複製に少し時間がかかります。終わるまで待ってください。

元に戻したいとき

アレンジの途中で動かなくなり、直せなくなったら、コピーからやり直せます。

  1. Android Studioで、そのプロジェクトのウィンドウを閉じます。
  2. Finderで 書類 → Kotlin を開きます。
  3. 動かなくなったほうのフォルダを1回クリックして選び、Enter を押します。名前を変えられるようになるので、A01HelloAndroid_old に変えます。
  4. 同じように、A01HelloAndroidのコピー の名前を A01HelloAndroid に変えます。
  5. Android Studioの Open から A01HelloAndroid を開き直します。
  6. もう一度アレンジを始める前に、上の「複製」の手順で、コピーを取り直します。

動かなくなったほうは、消さずに名前を変えるだけにしておくと、あとで見比べられます。

4. アレンジする

どこを、どれだけ変えるかは自由です。「何か所以上」という決まりはありません。文字の色を1か所変えるだけでも、アレンジです。JavaとSwiftを書いてきた人なら、処理そのものを足すところまでやっても構いません。下の表は、左から右へいくほど手が込んだものになっています。

変えられるものの例

変えるもの変える場所書き方の例
文字の色activity_main.xml の、文字を出す部品（TextView など）android:textColor="#FF0000"
画面の背景の色activity_main.xml の、いちばん外側の部品android:background="#FFF4D5"
ボタンの色activity_main.xml の Buttonandroid:backgroundTint="#008000"
ボタンや見出しの文言activity_main.xml の android:textandroid:text="ここをおして！"
画面に出すメッセージMainActivity.kt の、" " で囲まれた文字列Snackbar.make(view, "アレンジしました！", Snackbar.LENGTH_SHORT).show()
数値MainActivity.kt の中の数字問題の数、待ち時間、増やす量など
処理を足すMainActivity.kt押した回数を数える、値によって出す文字を変える、ボタンをもう1つ足して動かす、など

これは例です。表にないところを変えても構いません。

ボタンの色は android:background では変わりません

ボタンに android:background を書いても、色は変わらず、角の丸みだけがなくなります。ボタンの色を変えるときは、android:backgroundTint を使います。

変えると動かなくなりやすいところ

次の3つは、変えてはいけないわけではありません。ただ、1か所変えると、ほかの場所も合わせて直す必要があり、ビルドが通らなくなったり、アプリが起動しなくなったりすることがあります。

  • クラスの名前（MainActivity など）
  • パッケージ名（jp.ac.jec. で始まる名前）
  • AndroidManifest.xml の中身

変えてみたいときは、手順3のコピーがあることを確かめてから始めてください。

例：ボタンの文言と、メッセージを変える

やり方を1つ示します。ボタンに出ている文字と、ボタンを押したときに出るメッセージを、両方変えます。

まず、ボタンの文言です。app → res → layout → activity_main.xml を開き、エディタ右上の Code を選んで、変えたい Button を探します。

activity_main.xml · 変える前
        android:text="おす" />
activity_main.xml · 変えたあと
        android:text="ここをおして！" />

/> は「この部品の設定はここまで」という印です。" " の中だけを書き換えれば、ほかの行は触りません。

次に、メッセージです。app → java → jp.ac.jec.（プロジェクトごとの名前） → MainActivity.kt を開きます。

MainActivity.kt · 変える前
        val button: Button = findViewById(R.id.button)
        button.setOnClickListener { view ->
            Snackbar.make(view, "こんにちは", Snackbar.LENGTH_SHORT).show()
        }
MainActivity.kt · 変えたあと
        val button: Button = findViewById(R.id.button)
        button.setOnClickListener { view ->
            Snackbar.make(view, "アレンジしました！", Snackbar.LENGTH_SHORT).show()
        }

変えたのは " " の中の文字だけです。R.id.button や変数の名前は、自分のプロジェクトに合わせて読み替えてください。行の並びが自分のコードと少し違っていても、" " の中を書き換えるところは同じです。

もう一歩：押した回数を数える

処理を足すアレンジの例です。押すたびに1ずつ増える数を持たせ、その数をメッセージに入れます。

まず、MainActivity クラスの中、onCreate の手前に1行足します。

MainActivity.kt · クラスの中に足す
    private var tapCount = 0

Javaの private int tapCount = 0;、Swiftの private var tapCount = 0 と同じものです。Kotlinでは、書き換える変数を var、書き換えない変数を val で宣言します。型は 0 から推論されるので Int と書く必要はありません。

次に、ボタンを押したときの処理を2行にします。

MainActivity.kt · 変えたあと
        button.setOnClickListener { view ->
            tapCount++
            Snackbar.make(view, "${tapCount}回目", Snackbar.LENGTH_SHORT).show()
        }

"${tapCount}回目" は、文字列の中に値を差し込む書き方です。Swiftの "\(tapCount)回目" と同じ役目で、Javaの tapCount + "回目" のように + でつなぐ必要はありません。

変えたら、すぐRunして確かめる

1か所変えたら Run ▶ を押し、エミュレータで見た目と動きを確かめます。使うエミュレータは、授業で作った jec_25cm_kotlin_Pixel 9a です。まとめて変えてからRunすると、動かなくなったときに、どこが原因か分からなくなります。

成功の目印

アレンジしたところが、エミュレータの画面で確かめられる。アプリが、アレンジの前と同じように最後まで動く。

5. APKを作る

APKは、Androidにアプリをインストールするためのファイルです。アプリのコードと画像と設定が、1つのファイルにまとまっています。提出するのは、このファイルです。

用意するもの

アレンジが終わり、エミュレータでの動作確認が済んだ、自分のプロジェクト。

作るのはデバッグ用のAPKです。署名は要りません

APKには、開発中に使うデバッグ用と、ストアで配るためのリリース用があります。提出するのはデバッグ用です。デバッグ用には Android Studio が自動で印を付けるので、署名（signing）の作業は行いません。メニューにある Generate Signed App Bundle / APK は、この授業では使いません。

手順は次のとおりです。Android Studio は、授業の基準である Panda 2 のメニュー名で書いています。

  1. 提出するプロジェクトが開いていることを確認します。ほかのプロジェクトのウィンドウが開いているときは、閉じておくと間違えません。
  2. Run ▶ を押し、アレンジしたところを含めて、アプリが動くことを確かめます。
  3. 上の Build メニューを開きます。
  4. Build App Bundle(s) / APK(s) にカーソルを合わせ、出てきた中から Build APK(s) を選びます。
  5. 画面の下に進み具合が出ます。終わるまで待ちます。はじめの1回は数分かかることがあります。
  6. 右下に完了の通知が出ます。locate をクリックすると、できたファイルの場所がFinderで開きます。

成功の目印

右下の通知に APK(s) generated successfully のような文が出て、locate のリンクがある。

Runを押す操作とは別です

Run ▶ は、アプリをエミュレータに入れて動かす操作です。提出するファイルは作られません。提出するときは、かならず Build メニューからAPKを作ります。項目が見つからない場合は、メニューを開いたまま先生に見せてください。

教員と一緒に：メニューが見つからない場合

プロジェクト直下のTerminalで、次のコマンドでもデバッグ用のAPKを作れます。実行する場所に gradlew があることを確認します。

Terminal · プロジェクト直下
./gradlew :app:assembleDebug

BUILD SUCCESSFUL と出れば成功です。できるファイルの場所は、メニューから作ったときと同じです。

6. ファイルを見つけて、名前を変える

APKのファイル名は、どのアプリでも同じです

できあがるファイルは、どのプロジェクトでも app-debug.apk という名前になります。この名前のままでは、提出先の一覧で、誰のどのアプリなのか分かりません。作ったらすぐ名前を変えます。

ファイルを見つける

手順5の完了通知で locate をクリックすると、Finderでその場所が開きます。通知を消してしまったときは、Finderで 書類 → Kotlin → 自分のプロジェクト名 の順に開き、そこから app → build → outputs → apk → debug の順に進みます。

A01HelloAndroid の場合の保存場所
A01HelloAndroid/app/build/outputs/apk/debug/app-debug.apk
  1. app-debug.apk があることを確認します。
  2. Finderの更新日時を見て、今作ったファイルか確認します。日付が古いときは、別のプロジェクトのものです。
  3. app-debug.apk を選んで ⌘ C を押し、書類 など分かりやすい場所を開いて ⌘ V を押します。コピーなので、元の場所のファイルは残ります。

同じフォルダに output-metadata.json もあります

ビルドの情報が書かれたファイルで、提出には使いません。提出するのは、名前が .apk で終わるファイルだけです。

名前を変える

コピーしたファイルを1回クリックして選び、Enter を押すと、名前を変えられます。次の形にします。

提出用のファイル名の形
学籍番号_氏名_プロジェクト名.apk

学籍番号・氏名・プロジェクト名 は、それぞれ自分のものに置き換えます。区切りには半角の _ を使い、.apk の部分はそのまま残します。ファイル名の付け方は、先生の案内に従ってください。案内が別の形なら、そちらを優先します。

成功の目印

名前を変えたAPKが1つあり、ファイル名から、自分のものだと分かる。

7. Google Classroomに提出する

提出先は Google Classroom です。この授業の教材も Google Classroom で配られているので、同じクラスを開きます。

  1. ブラウザで Google Classroom を開き、この授業のクラスを選びます。
  2. 上の 授業 タブを開き、先生が出した提出課題をクリックします。
  3. 右側の 追加または作成 をクリックし、ファイル を選びます。
  4. 手順6で名前を変えたAPKを1つ選んで、アップロードします。
  5. アップロードしたファイル名が 学籍番号_氏名_プロジェクト名.apk の形になっていることを確認します。違っていたら、いったん削除して、名前を直してから入れ直します。
  6. 提出 をクリックし、表示が 提出済み に変わったことを確認します。

アップロードしただけでは提出になりません

ファイルを追加した状態と、提出した状態は別です。提出 を押して、表示が 提出済み に変わるところまで進めてください。押し忘れていると、先生の画面では「未提出」のままです。

成功の目印

課題の画面に自分のAPKが1つ表示され、提出済み になっている。

提出したあとでアプリを直したときは、動作確認 → APKを作り直す → 名前を変える の順でやり直します。Google Classroomでは 提出を取り消す をクリックすると、ファイルを入れ替えて出し直せます。締め切りを過ぎている場合は、先に先生に相談してください。

画面の表示がここに書いてあるものと違うときは、その画面のまま先生に見せてください。

8. うまくいかないとき

起きたことやってみること
アレンジしたらエラーが出て、直せないその画面のまま先生に見せる。やり直すときは、手順3の「元に戻したいとき」を見る。
ボタンの色が変わらないandroid:background ではなく、android:backgroundTint を使う。
ビルドが通らない（赤い文字が出る）画面の下に出ている赤い文字の中から、ファイル名と行番号を探し、その行を見直す。直せないときは、その画面のまま先生に見せる。
Build APK(s) が見つからないAndroid Studio の版が違うと、メニュー名が少し違うことがある。手順5の「メニューが見つからない場合」を、先生と一緒に行う。
完了の通知を消してしまい、APKの場所が分からないFinderで 書類 → Kotlin → 自分のプロジェクト名 → app → build → outputs → apk → debug の順に開く。
Android Studio の左の一覧に build フォルダが見えない左上の表示の切り替えが Android になっている。Project に変えると出る。Finderから探しても構わない。
app-debug.apk がない・更新日時が古い別のプロジェクトを開いたままAPKを作っていないか確認する。提出するプロジェクトを開き直し、手順5からやり直す。
APKのファイルサイズが小さすぎる気がするデバッグ用のAPKは数MB程度になる。極端に小さいときは、作り直して更新日時を確かめる。
提出先が分からない先生に確認する。この資料では決めていない。
提出できるアプリが1つもない先生に相談する。

表にないことが起きたら、その画面のまま先生に見せてください。
