A02CalcGame
授業の進め方

9〜10コマ目、各90分。Java・Swift学習済みの学生が、停止・再開するタイマーと10問の採点をKotlinで組み合わせます。

パッケージ：jp.ac.jec.a02calcgame / Android Studio Panda 2 / 指定AVD：jec_25cm_kotlin_Pixel 9a

1. 授業前の準備

  • Panda 2のEmpty Views Activity、Kotlin、Kotlin DSL、Minimum SDK API 31を確認する。Save locationは学生自身のDocuments/Kotlin/A02CalcGameまで含める。
  • 初回のGradle同期と指定AVDの起動を教室で確認する。指定AVDが既にある学生はそれを使う。新規作成が必要な学生にはAPI 31以上でCPUに合うシステムイメージを指定しておく。教材画像の実測環境はAPI 37.1・arm64-v8a・ライトテーマ。
  • Panda 2でも作成日によって依存の版が変わるため、STEP 01のlibs.versions.toml全文を使う。これは完成プロジェクトと一致する。教員の既定IDEはQuail 4なので、Panda 2の操作確認と混同しない。
  • 完成版で、START前の数字操作、START、STOP中の数字操作、STARTによる同一問題の再開、10問の結果、RESETを確認する。1問誤答・9問正答なら9問正解になる。
  • 9コマ目終了時は計時だけが動く。問題欄は空白、数字の処理はない。完成版の画面と比較して未完成の不具合だと扱わない。
  • 配布物のdocsとsamplesを同じ構成で用意する。見本のA02CalcGameと学生自身のA02CalcGameを保存先で区別する。

2. この単元の教材方針

中心はChronometerの基準時刻を使い、停止していた時間を除いて再開すること。9コマ目にタイマーを操作して効果を見て、10コマ目に既習の状態変数・条件分岐・繰り返し・メソッドを使ってゲームへ組み込む。Android側の新しい仕組みは計時に絞る。

判断理由
Java／Swiftとの対応でKotlinを説明変数や繰り返し自体の入門説明はしない。lateinitはJavaの後から代入するフィールド、intArrayOfはint[]、ラベル付きreturnはJavaのラムダ内returnと比べる。
View取得とリスナは既習の形を再掲A01を読み返さず、この教科書だけを前から読んで進めるため。生成時のインセット処理も残し、役割を本文で示す。
途中コードを段階ごとに用意先に完成ファイルを貼ってから読む形にしない。STEP 10の数字のSnackbarは配線確認用で、STEP 11で採点処理に置き換える。
オーナーの完成コードを保つgetBase()・setBase()・setEnabled()、文字列連結、isPlaying、answer == 0を説明する。ViewBinding、状態クラスへの分割、Unit Testのための変更は加えない。
乱数はThreadLocalRandomの1〜9最低API 31で使え、数字ボタンで全解答を入力できる。完成コード中の別APIのコメントは実行されないことだけ説明し、API分岐は追加しない。
ライフサイクル全体・状態保存を扱わない今回は画面を開いたままの計時・回答に集中する。回転・横画面・バックグラウンド復帰へ範囲を広げない。
アレンジは文字・余白・問題数既に出てきた範囲だけで、変更箇所と効果が見える。乱数範囲・引く元の数・数字ラベルを個別に変えると入力範囲や未開始の目印が壊れるため、例にしない。

Panda 3はオーナー決定により実測しない。Quail 4でのA02の操作・互換性を、このガイドでは確認済みとしない。異なる版は作成前に相談を受け、Panda 2用カタログだけを別の生成構成へ入れない。共通の版資料のA01実測結果をA02へ拡張して案内しない。

完成コードへのUnit Test、ダークテーマ、タブレット、画面回転、リリースAPKの署名は対象外。Kotlinのコンパイルと、エディタやLintの提案を区別する。警告を消すためのSuppressは追加しない。

4. 机間巡視と躓き

症状確認・対応
同期エラーPanda 2か、カタログが全文か、最初の原因行を確認する。別版のAGP番号だけを下げない。
Viewの取得で止まるsetContentViewより後か、XMLのidと型が合うかを確認する。txtMessageのlateinitは取得前に読まない。
停止中の時間まで加わるSTOPの「今 − base」とSTARTの「今 − 保存値」を対にして確認する。stop()はbaseを変えない。
問題が表示されないSTEP 08までは正常。STEP 09以降は、START内のifとstartQuestion呼び出し、txtMessageへの代入を確認する。
再開するたび問題が変わるif (answer == 0)の外でstartQuestionを呼んでいないかを見る。
数字を押すと落ちるXMLのボタン表示が整数の1〜9かを見る。toIntは数字以外の文字列を数へ変換できない。
10問目だけ採点されないnumber == answerの採点が、nowNoの終了分岐より前にあるか確認する。
RESET後に番号・正解数が残るelapsedTimeMillis、nowNo、correctNo、answer、isPlayingと問題欄のリセットをSTEP 09・12で照合する。
かっこの位置が違うonCreateの中のリスナ同士は並列、startQuestionはonCreateの外でクラスの内側。STEP 12の全文と途中コードを使う。

5. 終了時の確認と再開地点

区切り画面で確認すること再開地点
9コマ目START→STOP→STARTで時間が続き、STOP→RESETで00:00。問題欄は空白。STEP 07から同じA02CalcGameをOpen。
10コマ目停止中は案内だけ、再開時は同じ問題、10問で正解数と秒数、RESETで空白と00:00。アレンジはSTEP 13。提出時は共通APK資料。

未完了の学生は、最後に画面が一致したSTEPの次から再開する。チェック欄は端末内の進捗で、教員へ送信する機能はない。

理解確認に使う短い問い

問い期待する答えと確認操作
STOP後にSTARTを押しても問題が変わらないのはなぜかanswerが1〜9なのでanswer == 0に入らない。同じ式を表示したまま再開する。
5問版の条件を4にするのはなぜか1〜4問目の回答後だけ次問を作り、5問目は結果へ進むため。実際に5回回答して確かめる。
return@setOnClickListenerは何を終えるかその数字のクリック用ラムダ。停止中に押しても採点へ進まないことを画面で確かめる。

6. 照合用コードと保守

  • 01-libs.versions.toml：設定全文。完成版とバイト一致。
  • 02-activity_main.xml：画面全文。完成版とバイト一致。
  • 03-MainActivity.kt：View取得のみ。
  • 04-MainActivity.kt：STARTの計時のみ。
  • 05-MainActivity.kt：9コマ目終了時。停止・再開・RESET。
  • 08-MainActivity.kt：出題メソッドを定義した段階。まだ呼ばない。
  • 09-MainActivity.kt：STARTで出題し、停止・再開する段階。
  • 10-MainActivity.kt：数字の配線確認用Snackbarがある途中段階。
  • 12-MainActivity.kt：完成全文。完成版とバイト一致。

完成ソースはA02CalcGame。教科書の完成全文・XML・カタログとその複製をconfigで照合する。STEP 03の全文も照合コードと一致させる。変更した場合は配布ZIPを作り直す。

教材検査4種、assembleDebug、指定AVDの操作、途中コードのビルド、学生用ZIPを展開した後のリンクを確認する。検証用プロジェクトとログはリポジトリ外へ置く。本文で使う4枚の画像だけを配布する。
