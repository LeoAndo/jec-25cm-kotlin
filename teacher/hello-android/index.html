A01HelloAndroid
授業の進め方

Java・Swift学習済みの学生が、KotlinでXMLの部品を取得し、クリック時の処理を画面へつなぐ2コマです。7〜8コマ目、各90分。

パッケージ：jp.ac.jec.a01helloandroid / Android Studio Panda 2 / 指定AVD：jec_25cm_kotlin_Pixel 9a

1. 授業前の準備

  • 学生のMacでPanda 2のNew ProjectからEmpty Views Activityを選べることを確認する。教員の既定環境はQuail 4なので、操作確認にはPanda 2を明示して起動する。
  • 配布版のdocsとsamplesを同じ構成で用意する。学生は自分のDocuments/Kotlin/A01HelloAndroidを作る。samplesは比較用で、完成見本をそのまま提出しない。
  • Minimum SDKはAPI 31、Kotlin、Kotlin DSL、パッケージjp.ac.jec.a01helloandroid。Save locationはプロジェクト名まで入れる。
  • SDKとライブラリの初回ダウンロードが学内ネットワークで通るか、授業前に1台で確認する。ダウンロード待ちが20分を超える場合は、教員の端末で実行結果を見せて、学生はXMLの入力を進める。配布見本を自作として扱わない。
  • 指定AVDを起動する。表示名は jec_25cm_kotlin_Pixel 9a。内部のAVD識別子は空白が下線になる場合があるが、教科書・Device Managerの表示名は空白を使う。画像の実測環境はAPI 37.1・arm64-v8a・ライトテーマ。学生のシステムイメージは教室の配布環境で確認し、API 31以上かつCPUに合うものを授業前に指定する。
  • 完成版をRunし、起動時Hello World!、変更後Hello, Android!、「1」のSnackbar、「2」のToast、「3」は表示変化なしを確認する。Logcatの検索条件は package:jp.ac.jec.a01helloandroid tag:MainActivity level:DEBUG。
  • New Projectの生成値は作成日でも変わる。2026-09-24のPanda 2実測ではcoreKtxが1.19.0だった。教科書STEP 01のlibs.versions.toml全文は完成版の1.17.0を含む構成に固定し、configのsnippetsとmirrorsで一致を検査する。ひな形そのものは改変しない。

2. この単元の教材方針

中心はXMLのidを持つViewをKotlinで取得し、画面の操作へつなぐこと。UI部品・イベント処理はJava／Swiftの既習知識と比較する。Android側の新しい結び付け方を setContentView → findViewById → クリック登録の順で追い、結果を見出し・メッセージで確かめる。APIの一覧を覚えさせる構成にはしない。

判断理由
ActivityはonCreateの入口と親の呼び出しだけ画面を用意する位置が必要なため。ライフサイクル全体・再生成時の状態保持は、画面操作の目的を増やすため扱わない。
インセットの生成コードを残す画面端と内容が重ならないため。各コールバック・Insetsの詳細は導入しない。役割と「残す場所」を本文に書く。
LinearLayoutを文字で編集縦横とidを同じ画面で追えるため。ConstraintLayoutの制約編集、Compose、ViewBindingは扱わない。
Snackbar・Toastは同じクリック処理の出力先として比較呼び方はJavaと同じAPIで、利用者への結果が見える。Snackbarのアクション、独自Toast、通知権限などは加えない。
Logcatは画面表示と併用外側とラムダ内の実行タイミングを観測する補助。利用者への説明をLog.dだけにしない。
完成ソースのtext・button・btn1・btn2、getText()、括弧付きラムダ、@Overrideを維持既存のオーナーの書き方を説明する。命名や記法の整理のために完成ソースを改変しない。Kotlinで必要なのはoverrideキーワードで、注釈を必須だと教えない。
「3」は見た目の比較用で処理を付けないXMLのstyleとクリック処理が別であることを実物で確認できる。未実装の不具合と取り違えないよう本文にも明記する。
最後は文字と既存の余白の変更ここまでに扱った範囲で、変える場所と効果が結び付く。新しいAPIや機能をアレンジの条件にしない。例を正解にしない。

完成コードへのUnit Testの追加、ダークテーマ、回転・横画面、タブレット対応は対象外。IDEの黄色い提案をSuppressで隠さない。KotlinコンパイルとAndroid Lint／エディタの提案は区別する。XMLの直接の文字列や未使用のラムダ引数について、完成コードを勝手に書き換えず役割を説明する。

版の読み替えは共通資料のissue #5で扱う。A01本文の基準はPanda 2のままにする。Panda 3はオーナー決定により実測しない。Quail 4との差分は、リポジトリの2つのひな形とREADMEを基準にする。

4. 机間巡視と躓き

見るもの確認・対応
新規作成Empty Views Activity、API 31、保存先の末尾、パッケージを確認。Empty Activityには今回のXMLがない。
同期エラー先頭の原因を読む。libs.versions.tomlの全文と生成版を照合。Quail 4のDSLにAGP 9.1.1だけを入れる直し方はしない。
部品が見つからないXMLのmain/text/button/btn1/btn2とR.idを対応させる。setContentViewより前にfindViewByIdを書いていないか確認する。
かっこが増えた生成時の末尾ラムダと、見本の括弧付きラムダの両方は有効。部分追加時に両方の閉じ方を混ぜない。迷う場合はSTEP 11の全文と照合する。
クリックしても出ないクリック処理がonCreate内で並列に並んでいるか、別のクリック処理の内側に入っていないか、show()があるか確認する。
Logcatの行が多い端末・package・tag・levelを絞る。Stop→Run後の最新時刻を見て、クリック前後を区別する。
黄色い下線該当行とIDEの提案を読む。アプリがビルドできない赤いエラーと分ける。@SuppressLintは追加しない。

5. 終了時の確認と再開地点

区切り画面で確認すること次の再開位置
7コマ目Hello World!と4つのボタン。MainActivityには4つのView取得。クリック処理はまだない。STEP 07で同じプロジェクトをOpen。
8コマ目起動時Hello World!、変更後Hello, Android!、Snackbarの1、Toastの2、Logcatに2種類の文字。アレンジを続けるならSTEP 12。提出時は共通APK資料。

未完了の学生は、最後に画面が一致したSTEPの次から再開する。教科書のチェックを教員へ送る機能はない。完成見本を開いているだけの学生は、自分の保存先へ戻っているか確認する。

理解確認に使う短い問い

問い期待する答えと確認操作
btn1の表示を変えると何が変わるかボタンとSnackbarの文字。getText()で読んでいるため。XMLの文字だけを変更してRunする。
val textなのに文字を変えられるのはなぜか参照の再代入と、参照先Viewのプロパティ変更は別。クリック後の見出しを見る。
3でメッセージが出ないのはなぜかクリック処理を登録していない。XMLのstyleがあることと動作は別。

6. 照合用コードと保守

  • 01-libs.versions.toml：STEP 01の設定全文。完成版とバイト一致。
  • 04-activity_main.xml：STEP 04の画面全文。完成版とバイト一致。
  • 05-MainActivity.kt：STEP 05終了時の途中コード。通知・Logはまだなく、画面表示とView取得のみ。生成時の記法とは異なる部分があるが、完成版の骨格で照合できる。
  • 11-MainActivity.kt：STEP 11の完成全文。完成版とバイト一致。

完成ソースはA01HelloAndroidにある。変更する場合は教科書の全文、複製、配布ZIPを更新する。A01のsessionsは2。サイドバーにはconfigに登録された全単元を単元番号順に並べ、A01のtopbarは直前のK01を指す。

教材の検査4種、assembleDebug、指定AVDのクリックとLogcat、配布物のリンクを確認する。画像は本文で使う4枚だけを収録する。検証専用プロジェクトやログはリポジトリ外に置く。
