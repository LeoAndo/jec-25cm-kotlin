授業の進め方

11〜13コマ目、各90分。入力画面・固定データ・通信の結果の順に、同じ一覧へつなぎます。

1. 授業前の準備

  • Panda 2でEmpty Views Activityを選ぶ。初回同期用の回線とSDKを準備する。完成版はAGP 9.1.1／Gradle 9.3.1／compileSdk 36.1／targetSdk 36／minSdk 31。
  • 完成版をassembleDebugして指定AVDで起動。入力の案内、実検索、0件、検索条件エラー、通信中の印とボタン、スター数順を確認する。動的な件数や名前は一致条件にしない。
  • 教科書STEP 04・10の途中コードを別の検証用プロジェクトでRunしておく。11コマ目は入力Toast、12コマ目は2件の固定データ。通信できない時間もこの段階の照合を進められる。
  • 教室の出口IPが共有されるか、GitHubへの接続が制限されないかを学校の環境で確認する。この開発端末での通信成功を教室での成功とみなさない。
  • 配布物のdocsとsamplesの配置を保つ。見本のA03と学生自身のA03は保存先で区別する。

2. この単元の教材方針

中心はリストのデータを行のViewへ結び付け、固定データから通信結果へ差し替えること。受講生はJava・Swift学習済みなので、変数・クラス・例外そのものの入門説明はしない。画面の新しい主題はRecyclerViewのAdapter／ViewHolderによる一覧表示に置く。

判断理由
Java／Swiftとの対応を先に示すdata classは値をまとめる型、JSON変換はSwiftのCodable、suspendはasync、launchはTask、失敗分岐はtry/catch・do/catchに対応させる。これらの考え方をJavaにもSwiftにもない新概念として重ねて導入しない。
Android固有の接続箇所はその場で説明RecyclerView、ViewHolder、ListAdapter、lifecycleScope、INTERNETはAndroidの具体的なAPI名。継承・コールバック・非同期処理を比較で再利用し、仕組み全体の設計を新たな課題にしない。
Ktorの設定は完成版の必要な箇所だけapplyと同様に受け取り手のあるラムダで設定する形。install→json→Jsonの階層と未知の項目を無視する意味を説明し、DSLの自作やプラグイン開発へ広げない。
固定データを先に表示通信の失敗と行の配線の失敗を分けられる。受講生が同時にAPIを呼ばず、12コマ目の画面は回線なしでも同じになる。
オーナーの完成コードを保つfindViewById、ArrayAdapter.apply、Pair、runCatching、Toast、ListAdapterを説明する。ViewBinding、認証、別の状態クラス、テストのための分割を足さない。
検索結果は最大30件・先頭ページだけページングを扱わず、受け取ったitemsをそのまま表示。totalCountはモデルにあるが画面には出さない。
エラーの細分化をしない完成版は通信・JSON変換の失敗を同じToastへ送る。HTTP状態別の独自文言、再試行、キャッシュを教材の都合で追加しない。
ライフサイクル全体・状態保存は外す画面を開いたままの通信と表示に絞る。キャンセルの設計・画面回転・バックグラウンド復帰・ViewModelへ広げない。
アレンジは表示文字・余白・1回の取得上限既に扱ったコードの範囲で効果が見える。APIフィールドやid、sortの値を壊す変更は例にしない。

Panda 3はオーナー決定により実測しない。Quail 4でA03をこのガイドの手順どおり新規作成した結果も確認済みとしない。共通の版資料のA01実測をA03へ広げない。違う版は作成前に相談を受け、カタログの番号だけを下げない。

完成アプリのUnit Test、ダークテーマ、タブレット・フォルダブル、画面回転、リリースAPKの署名は対象外。警告を隠すSuppressは足さない。

4. 教室の通信と利用制限

認証なしのGitHub検索は1分間に10回まで。IP単位なので、同じ出口IPの教室では学生数ぶんの枠はない。一般のREST APIには別の制限もあり、「1人10回ならよい」と案内しない。最新の公式資料と応答ヘッダーで確認する。

教員が事前に1回、認証を付けない検索応答の x-ratelimit-limit・x-ratelimit-remaining・x-ratelimit-reset を確認する。合図のない再検索を止め、少人数ずつ実行する。枠が尽きたらリセット時刻まで待ち、連打で復帰を試さない。トークンを配布する形へ変更しない。

検証時、kotlin は通常の一覧、jec-a03-no-match-20260924-7d4a9c は0件、user:jec-a03-user-that-does-not-exist-20260924 は検索条件エラーの確認に使った。公開データは変わるため授業前に再確認する。0件は200の空items、失敗の例は422のエラーJSONで、完成版ではモデルへの変換が失敗する。Toast後半のエラー詳細は固定しない。

回線・制限で確認できない場合は、STEP 10の固定データで行の配線まで確認し、通信確認が未完了であることを残す。復旧後、STEP 14〜16の実検索・0件・失敗・並び順へ戻る。固定データを本物の検索結果として扱わない。

症状確認・対応
Gradle同期が失敗するSTEP 02の3つのファイルが正しい場所にあるか、Panda 2かを確認します。最初の原因行を先生に見せます。
Serializableが赤いSTEP 02のserializationプラグインと同期、STEP 07のimportを確認します。java.io.Serializableは使いません。
R.idが赤い／起動直後に閉じる2つのXMLのidと型、setContentViewの後での取得を照合します。行のViewはitemViewから探します。

検索しても入力のToastだけSTEP 04・10の途中コードです。STEP 14の完成コードへ進みます。
0件という案内通信は成功しています。入力語を確認し、次の検索は先生の合図を待ちます。
検索に失敗したまず連打をやめ、入力条件と回線・利用制限を先生と確認します。何度もRunすることでは制限は解除されません。
通信中の印が見えない速い応答では一瞬です。わざと連打せず、STEP 14のsetLoadingと呼び出し順を照合します。

途中から再開したい最後に画面が一致したSTEPの次から進みます。11コマ目末はSTEP 04、12コマ目末はSTEP 10の全文で照合できます。

理解確認に使う短い問い

問い期待する答え・確認操作
sortでfirstではなくsecondを送る理由firstは画面用の日本語、secondはAPIの値。スター数を選ぶとstarsを送る。
idが同じでも内容が違うのはいつか同じリポジトリのスター数などが変わったとき。data classの==で内容を比較する。
0件と失敗の違い0件は成功応答の空items。失敗は通信や変換の例外。両方空一覧でもToastが違う。
