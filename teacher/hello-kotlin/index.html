教員用ガイド
HelloKotlin

受講生は Java と Swift を学習済みです。この単元は「プログラミングの入門」ではなく、Java / Swift との差分の説明に時間を使います。1コマ90分、単元 K01HelloKotlin の1コマで完結させます。

1. 授業前の準備

  • 受講生像を全員の教員で共有します。受講生は Java と Swift を学習済みで、変数・型・条件分岐・繰り返し・クラスといった概念そのものの説明は不要です。説明するのは Kotlinでの書き方と、Java / Swift との違い、そして違う理由の3つです。
  • 学生には、教科書の docs フォルダと、展開済みの完成プロジェクトを入れた samples フォルダを、構成を保って配布します（完成プロジェクトのZIPも docs の中に残しています）。完成版は初回から自由に参照できます。teacher フォルダは配布しません。
  • 学生のMacで docs/hello-kotlin/index.html をブラウザで開けることを確認します。教材そのものにCDN・Webフォントは使いません。
  • Kotlin Playground（https://play.kotlinlang.org/）が、学内のネットワークとブラウザで開けることを授業前に確かめます。STEP 01でここから始めます。開けない教室では、STEP 01を教員の画面の実演だけにして、STEP 02のIntelliJ IDEAへ進みます。
  • IntelliJ IDEA と、Kotlinを動かすJDKを事前にそろえます。初回ダウンロードは下表の授業時間に含めません。授業で使うJDKの版を1つ決めて板書します。教科書では「先生が指定します」としか書いていません。
  • 学生の作成先を /Users/ユーザ名/Documents/Kotlin/プロジェクト名 に統一します。本人のユーザ名と、末尾が Documents/Kotlin/HelloKotlin になっていることを確認します。
  • 完成版の HelloKotlin を開き、src/ex01/main.kt を Run して、コンソールに 1 / 2.0 / 3.0 / Tanaka の4行が出ることを確認します。
  • はじめて授業を受ける学生には、共通資料：授業を始めるまでの準備を先に開かせます。
  • 本日の停止位置を板書します。

2. この単元の教材方針

この単元の主題は「Kotlinという言語を初めて書く」ことです。プログラミングの入門ではありません。受講生はすでに Java と Swift を書けるので、同じことを Kotlin ではどう書くか、そこで何が変わったかに集中させます。教科書の各STEPには、Java か Swift（または両方）との比較を必ず置いています。

方針理由授業での扱い
各STEPに Java / Swift との比較を必ず置く受講生は概念を知っていて、知らないのは書き方だけ。概念から説明すると、知っている話を聞く時間になり、90分が足りなくなる。前年度の資料も同じ方針で書かれている。教科書の比較ブロックを読ませたあと、「Javaなら何行になるか」を口で言わせる。教員は違いの理由（なぜKotlinはそう決めたか）を1文で足す。
導入の最初だけ Kotlin Playground を使い、STEP 02からは IntelliJ IDEA に移る環境構築で最初の10分を失うと、比較に使う時間がなくなる。ブラウザなら全員が同じ画面で1行目を動かせる。一方でPlaygroundはコード補完が効かず実行も遅いので、学習の本体には向かない。詳しくは「4. Playground と IntelliJ IDEA の使い分け」を参照。Playgroundは10分で切り上げる。
Build system に Gradle ではなく IntelliJ を選ばせるこの単元で見せたいのは val / var と型推論の差分だけ。Gradleを入れると、設定ファイル・同期待ち・依存関係の説明が増え、比較の時間を食う。Gradleは後半のAndroid系の単元で扱う。STEP 02の表で Build system を IntelliJ と指定している。HELPに「Build system に IntelliJ がない」の行を置いている。
学生にも src/ex01/ パッケージを作らせ、package ex01 を書かせるリポジトリの完成プロジェクト HelloKotlin は、純Kotlin系の単元を src/exNN/ で分ける構成にしている。学生の手元も同じ形にしておくと、見本と1対1で比べられ、行き先を言葉で指定できる。STEP 02で作らせる。Javaのパッケージと同じ考え方だと1文で伝え、Kotlinではフォルダ構成と一致させなくてもよいという細部には触れない。
val の再代入エラーを、STEP 03でわざと出させるJavaの final、Swiftの let を知っているので、説明より「自分の画面に出たエラー文」のほうが対応付けが早い。number1 = 5 を書き足させ、Val cannot be reassigned を確認させてから消させる。あわせて「val は再代入禁止であって、中身が変わらない保証ではない」ことを口で言う。
型を明示せず（val number1: Int = 1 と書かせず）、型推論のままにする完成コード HelloKotlin/src/ex01/main.kt がその形であり、教材と完成版をバイト単位で一致させているため。Swiftの型推論を知っている受講生には、書かないほうが差分が見えやすい。STEP 04で「名前にマウスを重ねると、決まった型が出る」と案内し、Swiftと効き方が違う場面（Float）だけを取り上げる。
コメント // Double / // Float を完成コードに残す完成プロジェクトの書き方をそのまま教材にしているため。型推論に任せた行がどの型になったかを、後から読み返す手がかりになる。STEP 04で「型推論の結果をコメントで補っている」とだけ説明する。KDocの書き方は扱わない。

この単元で意図的に扱わないこと

「あとの単元で扱う」と書いたものは、教科書の本文からは案内しません（他単元へ本文で送らない方針のため）。教員が口頭で「それは次回」と言う用途の表です。

扱わないこと理由どこで扱うか
Null安全（? / ?. / ?: / !!）受講生はSwiftのオプショナルを知っているので、比較の題材としては良いが、1コマに入れると差分が2つになる。今回の値はすべてnullにならないので、使わない記号を先に見せない。K02 NullSafety
関数を自分で作る（fun の定義・引数・戻り値）今回書く fun は main だけ。引数の書き方（引数名: 型）はSwiftと同じで、戻り値の書き方だけがJavaと違う。ここは1つの節を取って比較したい。K03 FunctionAndFlow
条件分岐と繰り返し（if / when / for）出力が4行で固定のため、なくても完成する。Javaとほぼ同じ書き方なので、説明の優先度も低い。K03 FunctionAndFlow
クラス・プロパティ・アクセサ（get() / set() / field）「値に名前を付ける」ところに集中させるため。プライマリコンストラクタと new 不要は、Javaとの差が大きく、1コマ分の題材になる。K04 ClassAndProperty
バイトコードの確認（Show Kotlin Bytecode → Decompile）この単元にはアクセサも自動生成コードもなく、見ても差分が現れない。バイトコードは「プロパティにアクセスするとアクセサメソッドが呼ばれている」ことを確かめるための道具なので、プロパティを扱う単元に置く。K04 ClassAndProperty
data class・スマートキャスト・拡張関数今回はクラスを作らない。拡張関数はSwiftの extension と同じ発想なので、比較の題材としてまとめて扱いたい。K05 DataClassAndExtension
コレクション（List / map）・by lazy値が4つしかないため、まとめて扱う必要がない。K06 CollectionAndLazy
Javaのプリミティブ型とラッパー型の詳細（int と Integer、オートボクシング、Kotlinの Int が何にコンパイルされるか）Kotlinでは Int と書くだけで、使い分けの判断が要らない。「Java側の事情がどう消えたか」を語り始めると、今日の主題である書き方の差分から離れ、実行時の話に入ってしまう。Java相互運用を扱う場面（この15コマでは扱わない）
Long / Short / Byte / Char / Boolean などの網羅完成コードにない型は出さない方針のため。型の一覧はJavaで学習済みで、Kotlinでも名前が違うだけ。使う3つ（Int / Double / Float）に絞り、リテラルの書き方の差（3.0f）だけを見せる。必要になった単元
文字列テンプレート（$name）と String の操作この単元の新概念を1つに保つため。$ を足すと「文字列の中と外」という別の話が増える。K02 NullSafety 以降
Gradle・依存ライブラリの追加コンソールアプリに追加するライブラリがない。ライブラリは必要なときだけ足す。Android系の単元
Unit Test完成プロジェクトにUnit Testは書かない方針のため。テストしやすくするためのリファクタリングもしない。扱わない

4. Playground と IntelliJ IDEA の使い分け

Kotlin Playground を使うのは、この単元のSTEP 01の1回だけです。STEP 02からはIntelliJ IDEAに移り、以降の単元でPlaygroundに戻ることはありません。

道具使う場面使わない理由
Kotlin PlaygroundSTEP 01。環境構築の前に、全員の画面でKotlinのコードが1回動くことを確かめる。コード補完が効かず、実行までに待ち時間がある。プロジェクトの形（パッケージ・ファイル・実行構成）が見えない。学習の本体には向かない。
IntelliJ IDEASTEP 02以降のすべて。純Kotlin系の単元（K01〜K06）はここで進める。最初の1行を出すまでに、JDKの選択とプロジェクト作成が必要。授業の冒頭に置くと、動く画面を見る前に止まる学生が出る。
Android Studio後半のAndroid系の単元（A01〜A04）。エミュレータ jec_25cm_kotlin_Pixel 9a を使う。この単元には画面もAndroid SDKも要らない。

前年度の資料（PDF）でも、Playgroundを導入に使いながら「本当は IntelliJ IDEA を使いたい」と書かれています。今年の教材は、その方針をそのまま採り、導入だけPlayground、本体はIntelliJ IDEA と決めています。授業中に「Playgroundのほうが楽だからこのまま進めたい」という声が出たら、コード補完と実行速度の2点を理由に、IDEへ移らせてください。

Playgroundを使うときの注意

  • 学内のネットワークとブラウザで開けるかを、授業前に教員が確認します。開けないときはSTEP 01を教員の実演だけにします。
  • 共有URLを作る機能（Share）は使わせません。課題の提出には使いません。この単元に提出物はありません。
  • 氏名・学籍番号など、個人が分かる文字列をコードに書かせないでください。外部のサービスです。
  • 実行結果が出るまでに待ち時間があります。「押したのに何も出ない」という質問が出るので、先に伝えてから押させます。

5. Java / Swift 経験者が躓きやすい点

ここに挙げるのは、プログラミングが初めてだから起きることではなく、JavaとSwiftを知っているから起きる間違いです。見回りで探す対象もこの表にそろえます。

症状原因（どの言語の癖か）その場での直し方
val を「中身まで変わらないもの」だと説明してしまう / そう受け取るJavaの final と同じで、再代入が禁止されるだけ。参照先のオブジェクトの中身は変えられる。Swiftの let は構造体では中身も変わらないため、Swift側の感覚とずれる。「val は名前の付け替えを禁止する。箱の中身の話ではない」と言い直す。この単元の値は数と文字列だけなので差は出ない。実際の差はコレクションを扱うK06で見せる、と伝えて先へ進む。
val number3: Float = 3.0 と書いて、赤いエラーが出るSwiftでは型注釈を書けばリテラルがその型になる。Kotlinでは 3.0 は Double のままで、Float へ暗黙に変換されない。3.0f と書かせる。「型を書けば合わせてくれる」のではなく「リテラルの書き方で型が決まる」という順序に直す。教科書STEP 04の比較表を一緒に読む。
f を付けずに Float のつもりで進み、型が Double になっているJavaでも float f = 3.0; はエラーだが、Kotlinは型を書かないのでエラーにならず通ってしまう。number3 にマウスを重ねて、推論された型を画面で見せる。出力の 3.0 だけでは見分けが付かないことを伝える。
行末にセミコロンを付けているJavaの癖。Kotlinはセミコロンを許容するのでコンパイルが通ってしまう。IDEの設定によっては弱い警告が出ることはあるが、赤いエラーにはならないため、指摘しなければ癖が残る。STEP 05で1回だけわざと付けさせ、動いてしまうことを見せてから全部消させる。以降の単元でも、見回りでセミコロンを探す。Swiftも不要だった、と対応付けると残りやすい。
class Main { public static void main(String[] args) { … } } の形を作ろうとするJavaの癖。Kotlinの fun main() はクラスの外（トップレベル）に書ける。Kotlin Class/File の一覧で File を選び直させる。Class を選んでできたファイルは消させる。クラスはK04で扱うと伝える。
System.out.println(…) または print(…) と書く前者はJavaの癖、後者はSwiftの癖。Kotlinの print は改行しないので、出力が1行につながって「4行出ない」という症状になる。println に直させる。print と println の違いは、1回実行して見せるほうが早い。
int number1 = 1; のように型を先に書くJavaの癖。Kotlinは val 名前: 型 = 値 の順で、Swiftと同じ並び。Swiftの書き方を思い出させる。この単元では型注釈そのものを書かせないので、val number1 = 1 に直させる。
Kotlinの var を、Javaの var（型推論）と同じものだと考えるJava 10以降の var は型を書かないという意味で、再代入はできる。Kotlinの var / val は再代入できるかどうかの区別で、型推論は両方に効く。「Kotlinでは型推論は既定で効いていて、var / val はそれとは別の話」と1文で整理する。val number1: Int = 1 も書けることを口で言うにとどめる。
Build system が Gradle のままプロジェクトができている画面の既定値のまま Create を押した。できたプロジェクトを閉じ、フォルダごと消して作り直す。教科書STEP 02の表を一緒に読む。
src の直下に main.kt ができているパッケージを作る手順を飛ばした。ex01 を作り、main.kt をドラッグで移動する。1行目が package ex01 になることを一緒に確かめる。
緑の ▶ が出ないfun main() のつづり違い、または () の抜け。教科書のコードと1文字ずつ照合する。Main や mian がないか見る。
Run を押しても何も起きないJDKが選ばれていない。プロジェクト設定でJDKを選ぶ。未ダウンロードなら Download JDK を始め、待つ間はPlaygroundで続きを書かせる。
赤い波線が消えない全角スペース、全角の引用符、全角のかっこが混ざっている。入力が英数字になっているか確認し、その行だけを消して打ち直させる。
完成チェックで動かないSTEP 03やSTEP 05で書き足した行（number1 = 5 やセミコロン）を消していない。書き足した行を探して消す。最後の3分を必ず取る。

6. 机間巡視の確認項目

見回りのときに、この順で画面を見ます。上から3つは全員、残りは気になる学生だけで構いません。

見る場所OKの状態NGのときの声かけ
ウィンドウのタイトルと保存先Documents/Kotlin/HelloKotlin で終わっている。「フォルダはどこにありますか」と聞き、Finderで開かせる。
main.kt の1行目package ex01 と書いてある。「ファイルはどのフォルダに入っていますか」と聞き、src/ex01/ へ移動させる。

fun main() の位置クラスの中に入っていない。「このファイルに class はありますか」と聞く。
val と var の使い分けname だけが var。ほかの3つは val。「あとから入れ替えるのはどれですか」と聞き、その行だけ var にさせる。
number3 の行3.0f と書いてある。マウスを重ねると Float と出る。「型は何になっていますか」と聞き、画面で確かめさせる。
出力（Run のあと）コンソールに 1 / 2.0 / 3.0 / Tanaka の4行。「何行出るはずですか」と先に言わせてから、もう一度実行させる。
STEP 05のあとの状態練習で書き足した行が消えている。完成版と1行ずつ見比べさせる。

理解確認に使う短い問い

Java / Swift の知識に引っかける問い方にします。用語を暗記できたかは見ません。

問い見たい答え・行動
Javaの final に当たるのは val と var のどちら？val と答える。あわせて「再代入できないだけ」と言えれば十分。

行末のセミコロンは必要？不要、と答える。Swiftと同じだと対応付けられれば十分。
main はクラスの中に書く？不要、と答える。Javaとの違いとして言えれば十分。
自分のプロジェクトはどこにある？Documents/Kotlin/HelloKotlin と言う、またはFinderで開く。
