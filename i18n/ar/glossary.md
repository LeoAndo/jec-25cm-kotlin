# 用語集：العربية（ar）

Kotlin演習の対訳表。訳すときは、この表の訳語を使う。新しく訳語を決めた用語は、行を足す。全言語に共通の翻訳ルールは `skills/translate-teaching-materials/SKILL.md` にある。メモに「要確認」とある行は、訳語に自信がないもの。翻訳PRで確かめたら「要確認」を消す。

**アラビア語は右から左に書く（#78）。** 翻訳ページには `dir="rtl"` が付き、コード・キー・未翻訳の日本語は左から右のまま出る。ただし、訳文に日本語や英語のまま残す部分は左から右に並ぶので、その書き方に決まりがある（下の「書き方の決まり」。記号で終わる言葉のうしろには `&lrm;` を書く）。訳文は現代標準アラビア語（فصحى）で書く。方言は使わない。

## 書き方の決まり

「ここから下は、この授業だけの決まり」の前までは、jec-25cm-hybrid-app の `i18n/ar/glossary.md`（main `9c01c82`）と同じ文面にしてある（#96）。変えるときは、あちらも同じように直す。右から左の文の中での見え方は、文字ごとの表示位置を測って確かめた（2026-09-25。こちらは #78・#96 で Chromium系のブラウザ、あちらは #39 で Google Chrome）。

- **日本語や英語のまま残す言葉が記号（。、…！？）で終わるときは、その記号のすぐうしろに `&lrm;` を書く。** 書かないと、うしろに続くアラビア語や文の終わりに引かれて、その記号が言葉の反対側へ回り込み、「。保存した記録を読み込みました」「…File &gt; Open Folder」のように見える。この決まりは2026-09-25のオーナー決定で、jec-25cm-hybrid-app でも同じにしている（#96）。
  - **文字そのもの（U+200E）ではなく、`&lrm;` という6文字で書く。** カタログの上で目に見えるので、レビューで見落とさず、コピーしたときにも紛れ込まない。`&lrm;` はページでは「左から右」を示す見えない文字になる。向きを変える見えない文字（U+200E・U+200F・U+061C・U+202A〜U+202E・U+2066〜U+2069）をそのまま入れた訳は、対訳カタログの検査（`check`・`merge`）で落ちる。

  例文は jec-25cm-hybrid-app の教材の文。この授業の教材で当てはまる文が出たら、ここに足す。

  ```text
  原文：「保存した記録を読み込みました。」、追加した習慣、回数、詳細の理由を確認します。
  訳文：تحقق من ظهور 「保存した記録を読み込みました。&lrm;」 (تم تحميل السجل المحفوظ.)، ومن العادة المضافة، …
  原文：File &gt; Open Folder…でF01StampBoardそのものを開く。
  訳文：افتح F01StampBoard نفسه من File &gt; Open Folder…&lrm; في Visual Studio Code، …
  ```

  次の場合は書かなくてよい。どれも正しく並ぶことを確かめてある。
  - `<code>`・`<kbd>` の中（<code>プロジェクト → 公開…</code>、<code>let count = 0;</code>）。CSSで左から右に並べている。
  - `<strong>` の中（<strong>好きなものノートを作ります。</strong>）。CSSで、中の最初の文字の向きに並べている。
  - 記号で終わらない言葉（「テキストを変更」）。
- **「」は、日本語のまま残す言葉を囲むときだけ使う。** 右から左の文の中でも、かっこは向きを反転して正しく囲む形で出る。
- **アラビア語で書く操作や処理の並びは、矢印を ←（U+2190）にする。** 右から左に読むので、次の段階は左にある。→ のままだと、逆の順番に見える。日本語や英語のまま残す部分の中の → は、原文のまま残す（その部分は左から右に並ぶ）。

  ```text
  原文：入力→追加→詳細→戻る→再読み込みの順で動かし、
  訳文：شغّل التطبيق بالترتيب: الإدخال ← الإضافة ← التفاصيل ← الرجوع ← إعادة التحميل، …
  原文：クラウド IDEの <code>プロジェクト → 公開…</code> を開き、
  訳文：افتح <code>プロジェクト → 公開…</code> (مشروع ← نشر…) في بيئة التطوير السحابية، …
  ```

- **`<strong>` の中は、英字や日本語で書き始めてアラビア語を続けない。** `<strong>` は中の最初の文字で向きが決まるので、英字で始めると左から右に並び、読む順が逆になる。アラビア語を先に書く（<strong>ملف Dart</strong>）か、英字・日本語だけを入れる。
- **数字は 0〜9（西洋数字）で書く。** STEP番号・コード・画面の表示と同じ数字にする。アラビア・インド数字（٠١٢٣）は使わない。
- **句読点はアラビア語のものを使う。** 読点は「،」、疑問符は「؟」、セミコロンは「؛」。文末は「.」。
- **引用符は «…»。** 画面やアプリに出る日本語を囲むときは「」のまま残す（上の決まり）。
- **手順と学生への呼びかけは、命令形の男性形を総称として使う**（افتح، اختر، انقر）。アラビア語のソフトウェアの手順書の慣例に合わせた。先生は المعلم と書く。`config/i18n.json` のUI文言と翻訳の注記（فاسأل المعلم）も、この書き方にそろえてある。要確認（学生本人に、違和感がないかを確かめる）。
- **母音記号（ハラカート）は付けない。** 読み違えやすい語だけ、シャッダ（ّ）を付けてよい（نزّل، شغّل）。
- **英字の製品名やコード名に、定冠詞 ال を直接付けない。** 名詞を添えて書く（إطار Flutter، حزمة shared_preferences）。

ここから下は、この授業だけの決まり。

- **「次へ」のリンクの矢印も ← にする**（الانتقال إلى K01：HelloKotlin ←）。上の決まりの、この授業の教科書での例。
- **画面の名前をつないだ経路は、原文の言葉と → をそのまま残す**（**File → New → Project…**、**新規 → パッケージ**）。画面は左から右に並んでいるので、→ のままでよい。訳はうしろのかっこに添え、かっこの中の経路はアラビア語なので ← でつなぐ（**表示 → ツールウィンドウ → 実行** (عرض ← نوافذ الأدوات ← تشغيل)）。経路の途中の語だけを訳すと、向きの違う語が混ざって順番が読めなくなるので、経路の中は訳さない（**書類 → Kotlin → 自分のプロジェクト名** (المستندات ← Kotlin ← اسم مشروعك)）。
- 確認欄（ここで止まって確認）は、画面で確かめられる状態を現在形で書く（يظهر…、تُعرض…）。「〜できた」「〜と言えた」のような振り返りの言い方にしない。
- Kotlin固有の用語を定義する文では、訳語のうしろに日本語をかっこで添える（المُنشئ الأساسي (プライマリコンストラクタ)）。
- 全角の記号はASCIIにする（`＋` → `+`、`〜` の範囲 → en dash `–`）。サイドバーの「番号＋全角スペース＋題名」の全角スペースだけは残す。
- **「戻る」のリンクの矢印は → にする**（→ العودة إلى الصفحة الأصلية）。右から左に読むので、戻る向きは右になる。「次へ」の ← と逆になる。
- **URLをそのまま書いたリンクの文字は、末尾の / を落とす**（リンクの文字を `https://play.kotlinlang.org` にする。`href` は原文のまま変わらない）。右から左の文の中では、URLの最後の / が、URLの反対側（先頭の左）へ回り込んで見えるため（#81、Chromium系のブラウザで確かめた）。`/` は上の `&lrm;` の決まりの記号（。、…！？）に入っていないので、#81 で決めたこの書き方のままにする。
- 上の「母音記号は付けない」は、タンウィーンも含む（أولا、تلقائيا）。上の表の مُعامِل・المُنشئ は、#78 で読み違えを避けるつもりで母音記号を付けた訳語で、#81 でも「読み違えやすい語」の例外としてそのまま使った。上の決まりの例外として扱う。
- 上の「ال を直接付けない」の、この授業での例：جهاز Mac、مشروع Kotlin。
- 日付は 23 سبتمبر 2026 の形にする（月はグレゴリオ暦の名前 يناير … ديسمبر）。
- 表の見出し（使うもの、場所、項目など）は、同じ原文のほかのページの表にも同じ訳が入る。特定の表の中身に寄せず、どの表でも通じる言い方にする（使うもの → ما تستخدمه）。見出しと表の見出しの両方に出る原文（進め方）も同じで、どちらでも通じる訳にする（طريقة المتابعة）。
- **英語のまま残す経路が `<strong>` の外にまたがるときは、経路の終わりに `&lrm;` を書く**（`Phone and Tablet → <strong>Empty Views Activity</strong>&lrm;.`）。→ と `<strong>` は、左から右の文字にはさまれると左から右の並びに入るので、経路全体が Phone and Tablet → Empty Views Activity の順で読める。`&lrm;` がないと、→ が右から左の側に取られて、Empty Views Activity ← Phone and Tablet と逆向きに見える。文末の「.」は `&lrm;` のうしろに書くと、経路の左側（続くアラビア語の側）に付く。上の `&lrm;` の決まりの、この授業での例（#167、Chromium系のブラウザで文字ごとの表示位置を測って確かめた：P が x=417、→ が 533、Empty の E が 550、文末の「.」が 413、続くアラビア語が 405）。
- **経路のうしろ半分が英語のフォルダ名だけのときは、かっこの中の訳でも、その部分は → のまま残す**（**書類 → Kotlin → 自分のプロジェクト名 → app → build → outputs → apk → debug** (المستندات ← Kotlin ← اسم مشروعك، ثم app → build → outputs → apk → debug)）。英字の語と英字の語にはさまれた ← は左から右の並びに入り、app ← build のように逆向きに見えるため。アラビア語の語がとなりにある Kotlin のような1語だけの英字は、← でつないでよい（上の決まりの例）。確認用ページでは、右から المستندات ← Kotlin ← اسم مشروعك، ثم と読み、そのあと app → build → outputs → apk → debug を左から右に読む形で出る（#167）。
- **`<strong>` の中に操作の並びを書くときは、アラビア語から始めて ← でつなぐ**（**動作確認 → APKを作り直す → 名前を変える** → <strong>التحقق من عمل التطبيق ← إعادة إنشاء ملف APK ← تغيير الاسم</strong>）。上の「操作や処理の並びは ←」と「`<strong>` の中はアラビア語から」の、この授業での例（#167）。
- 「手順4・手順5」のように2つ並ぶときは الخطوتان 4 و5（上の表の「手順」の行の、2つのときの形）。
- Google Classroom の表示名と Finder の **複製** は、日本語のまま残して表示名をかっこで添える（上の表）。「未提出」のように「」で囲んだ表示は、「」のまま残す（「未提出」 (لم يتم التسليم)）。`docs/common/apk.html` の「複製」は `<strong>複製</strong> (تكرار)`、「複製」の手順は 「複製」 (تكرار) と、原文の囲みのまま書く。
